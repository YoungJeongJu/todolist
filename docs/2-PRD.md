## 2. 제품 개요

### 목적

인증된 사용자가 개인별로 격리된 공간에서 할 일을 생성·관리할 수 있는 웹 애플리케이션을 제공한다.

### 핵심 문제

| #   | 문제                                                 |
| --- | ---------------------------------------------------- |
| 1   | 사용자별로 격리된 할 일 관리 공간이 없다             |
| 2   | 시작일·종료일 기반으로 할 일의 상태를 추적할 수 없다 |

### 목표 사용자

- 학생
- 20~50대 직장인

## 4. 기능 요구사항

### REQ-AUTH — 인증

#### UC-01: 회원가입

- **As a** 신규 방문자
- **I want to** 이메일·비밀번호·이름으로 계정을 생성하고 싶다
- **So that** 개인 할 일 공간을 사용할 수 있다

**인수 조건 (AC)**

| AC#   | 조건                                                 |
| ----- | ---------------------------------------------------- |
| AC-01 | 이메일은 이메일 형식이어야 하며 중복 불가            |
| AC-02 | 비밀번호는 최소 8자, 영문+숫자 포함 필수             |
| AC-03 | 이름은 1~50자                                        |
| AC-04 | 가입 성공 시 '기본' 카테고리가 자동 생성된다 (BR-05) |
| AC-05 | 가입 성공 즉시 로그인 상태가 된다                    |
| AC-06 | 가입 시 themeMode 기본값은 LIGHT (REQ-THEME)         |

---

#### UC-02: 로그인

- **As a** 가입된 사용자
- **I want to** 이메일·비밀번호로 로그인하고 싶다
- **So that** 내 할 일에 접근할 수 있다

**인수 조건 (AC)**

| AC#   | 조건                                                         |
| ----- | ------------------------------------------------------------ |
| AC-01 | 이메일·비밀번호 일치 시 인증 토큰 발급                       |
| AC-02 | 불일치 시 명확한 오류 메시지 표시                            |
| AC-03 | 미인증 상태에서 앱 기능 접근 시 로그인 화면으로 이동 (BR-01) |
| AC-04 | 로그인 성공 시 저장된 themeMode가 즉시 적용된다 (REQ-THEME)  |

---

#### UC-03: 내 정보 수정

- **As a** 로그인된 사용자
- **I want to** 내 이름 또는 비밀번호를 변경하고 싶다
- **So that** 계정 정보를 최신 상태로 유지할 수 있다

**인수 조건 (AC)**

| AC#   | 조건                                                                   |
| ----- | ---------------------------------------------------------------------- |
| AC-01 | 이름(1~50자), 비밀번호(최소 8자, 영문+숫자) 수정 가능 (BR-02)          |
| AC-02 | 비밀번호 변경 시 현재 비밀번호 확인 절차 수행                          |
| AC-03 | 타인의 정보는 수정 불가 (BR-04)                                        |
| AC-04 | themeMode(LIGHT \| DARK) 변경 가능하며 변경 즉시 저장·적용 (REQ-THEME) |

---

#### UC-04: 회원 탈퇴

- **As a** 로그인된 사용자
- **I want to** 내 계정을 삭제하고 싶다
- **So that** 서비스 사용을 종료하고 개인정보를 삭제할 수 있다

**인수 조건 (AC)**

| AC#   | 조건                                                                      |
| ----- | ------------------------------------------------------------------------- |
| AC-01 | 탈퇴 시 해당 사용자의 모든 할 일·카테고리('기본' 포함)가 삭제된다 (BR-03) |
| AC-02 | 탈퇴 전 확인 절차(비밀번호 재입력 또는 확인 다이얼로그) 제공              |
| AC-03 | 탈퇴 후 로그인 화면으로 이동                                              |

---

### REQ-CAT — 카테고리 관리

#### UC-05: 카테고리 생성

- **As a** 로그인된 사용자
- **I want to** 새 카테고리를 만들고 싶다
- **So that** 할 일을 목적별로 분류할 수 있다

**인수 조건 (AC)**

| AC#   | 조건                                          |
| ----- | --------------------------------------------- |
| AC-01 | 카테고리 이름은 1~30자                        |
| AC-02 | 생성된 카테고리는 본인에게만 표시된다 (BR-04) |

---

#### UC-06: 카테고리 삭제

- **As a** 로그인된 사용자
- **I want to** 불필요한 카테고리를 삭제하고 싶다
- **So that** 카테고리 목록을 간결하게 유지할 수 있다

**인수 조건 (AC)**

| AC#   | 조건                                                                |
| ----- | ------------------------------------------------------------------- |
| AC-01 | '기본' 카테고리(isDefault=true)는 삭제 불가 (BR-06)                 |
| AC-02 | 삭제 시 해당 카테고리의 할 일은 '기본' 카테고리로 자동 이관 (BR-07) |
| AC-03 | 삭제 전 확인 절차 제공                                              |

---

### REQ-TODO — 할 일 관리

#### UC-07: 할 일 등록

- **As a** 로그인된 사용자
- **I want to** 제목·설명·시작일·종료일·카테고리를 지정하여 할 일을 등록하고 싶다
- **So that** 해야 할 작업을 체계적으로 기록할 수 있다

**인수 조건 (AC)**

| AC#   | 조건                                                 |
| ----- | ---------------------------------------------------- |
| AC-01 | 제목은 1~100자 필수 입력                             |
| AC-02 | 설명은 최대 1000자, 선택 입력                        |
| AC-03 | 시작일·종료일은 캘린더 UI로 선택, 모두 선택 사항     |
| AC-04 | 종료일 >= 시작일 (BR-09)                             |
| AC-05 | 카테고리 미지정 시 '기본' 카테고리 자동 적용 (BR-08) |
| AC-06 | 등록 시 기본 상태는 NOT_STARTED                      |

---

#### UC-08: 할 일 수정

- **As a** 로그인된 사용자
- **I want to** 등록한 할 일의 내용을 수정하고 싶다
- **So that** 변경된 일정이나 내용을 반영할 수 있다

**인수 조건 (AC)**

| AC#   | 조건                                       |
| ----- | ------------------------------------------ |
| AC-01 | 제목·설명·시작일·종료일·카테고리 수정 가능 |
| AC-02 | 수정 시에도 AC-01~05(등록 규칙) 동일 적용  |
| AC-03 | 본인의 할 일만 수정 가능 (BR-04)           |

---

#### UC-09: 할 일 삭제

- **As a** 로그인된 사용자
- **I want to** 불필요한 할 일을 삭제하고 싶다
- **So that** 목록을 정리할 수 있다

**인수 조건 (AC)**

| AC#   | 조건                             |
| ----- | -------------------------------- |
| AC-01 | 본인의 할 일만 삭제 가능 (BR-04) |
| AC-02 | 삭제 전 확인 절차 제공           |

---

#### UC-10: 상태 변경

- **As a** 로그인된 사용자
- **I want to** 할 일의 상태를 미시작·진행 중·완료로 변경하고 싶다
- **So that** 작업 진행 현황을 추적할 수 있다

**인수 조건 (AC)**

| AC#   | 조건                                               |
| ----- | -------------------------------------------------- |
| AC-01 | 상태 값은 NOT_STARTED / IN_PROGRESS / DONE 중 하나 |
| AC-02 | 상태는 사용자의 명시적 조작으로만 변경된다 (BR-10) |
| AC-03 | 날짜 변경으로 상태가 자동 전이되지 않는다 (BR-10)  |

---

### REQ-FILTER — 필터링

#### UC-11: 상태별·기한 초과 필터링

- **As a** 로그인된 사용자
- **I want to** 상태(미시작·진행 중·완료·기한 초과)별로 할 일을 필터링하고 싶다
- **So that** 현재 집중해야 할 항목을 빠르게 파악할 수 있다

**인수 조건 (AC)**

| AC#   | 필터      | 판정 기준                                                  |
| ----- | --------- | ---------------------------------------------------------- |
| AC-01 | 미시작    | status=NOT_STARTED AND dueDate >= 오늘 (또는 dueDate 없음) |
| AC-02 | 진행 중   | status=IN_PROGRESS AND dueDate >= 오늘 (또는 dueDate 없음) |
| AC-03 | 완료      | status=DONE                                                |
| AC-04 | 기한 초과 | dueDate < 오늘 AND status != DONE                          |

---

#### UC-12: 카테고리별 필터링

- **As a** 로그인된 사용자
- **I want to** 특정 카테고리의 할 일만 보고 싶다
- **So that** 분야별로 작업 현황을 파악할 수 있다

**인수 조건 (AC)**

| AC#   | 조건                                                 |
| ----- | ---------------------------------------------------- |
| AC-01 | 카테고리 선택 시 해당 categoryId를 가진 할 일만 표시 |
| AC-02 | 상태별 필터와 카테고리 필터 동시 적용 가능           |

---

### REQ-THEME — 테마 선택 (v2)

#### UC-13: Dark/Light 모드 선택 및 저장

- **As a** 로그인된 사용자
- **I want to** Dark 모드와 Light 모드를 선택하고 싶다
- **So that** 내 환경에 맞는 화면으로 앱을 사용할 수 있다

**인수 조건 (AC)**

| AC#   | 조건                                                            |
| ----- | --------------------------------------------------------------- |
| AC-01 | 사용자는 LIGHT / DARK 중 하나를 선택할 수 있다                  |
| AC-02 | 선택한 themeMode는 User 레코드에 즉시 저장된다                  |
| AC-03 | 다음 로그인 시 저장된 themeMode가 자동 적용된다                 |
| AC-04 | 테마 변경은 페이지 전환 없이 즉시 전체 UI에 반영된다            |
| AC-05 | 미로그인 사용자(로그인·회원가입 화면)는 기본값 LIGHT로 표시된다 |

> **도메인 영향**: User 엔티티에 `themeMode Enum(LIGHT, DARK) NOT NULL default LIGHT` 속성 추가 필요 (`1-domain-definition.md` v2 반영 대상)

### REQ-I18N — 다국어 지원 (v2)

#### UC-14: 언어 선택

- **As a** 사용자
- **I want to** UI 언어를 선택하고 싶다
- **So that** 내 모국어로 앱을 사용할 수 있다

**인수 조건 (AC)**

| AC#   | 조건                                                                        |
| ----- | --------------------------------------------------------------------------- |
| AC-01 | v2 지원 언어: 한국어(ko), 영어(en)                                          |
| AC-02 | 언어 선택 UI는 헤더 또는 설정 화면에서 접근 가능하다                        |
| AC-03 | 선택한 언어는 브라우저 로컬스토리지에 저장되며, 재방문 시 유지된다          |
| AC-04 | 모든 UI 텍스트(버튼, 레이블, 에러 메시지, 플레이스홀더)에 다국어가 적용된다 |
| AC-05 | 언어 변경은 페이지 전환 없이 즉시 반영된다                                  |

> 언어 설정은 기기/브라우저 단위 설정으로 간주하여 User 레코드에 저장하지 않는다. (themeMode와 구분)
