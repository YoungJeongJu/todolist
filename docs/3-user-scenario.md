```
  │                    │                                          └── 재시도

  │                                          └── 중복 이메일 ──▶ 오류 (US-18)
  └── 예 ──▶ themeMode 복원 ──▶ [메인 화면]
```

### 3-2. 핵심 기능 흐름 (v1)

```
[메인 화면 — 로그인 상태]
      │
      ├─── [카테고리 관리]
      │         ├── 생성 (US-05): 이름 입력 → 저장
      │         └── 삭제 (US-06): 확인 → 삭제 → 할 일 '기본'으로 이관
      │
      ├─── [할 일 관리]
      │         ├── 등록 (US-07): 제목·날짜·카테고리 입력 → NOT_STARTED로 저장
      │         │       └── 날짜 오류 시 차단 (US-19)
      │         ├── 수정 (US-08): 편집 화면 → 저장
      │         ├── 삭제 (US-09): 확인 → 삭제
      │         └── 상태 변경 (US-10): NOT_STARTED → IN_PROGRESS → DONE
      │                                  └── 날짜 변경으로 자동 전이 없음
      │
      ├─── [할 일 목록 필터링]
      │         ├── 상태별 (US-11): 미시작 / 진행 중 / 완료 / 기한 초과
      │         └── 카테고리별 (US-12): 카테고리 선택 → 상태 필터 동시 적용 가능
      │
      └─── [내 정보 수정 (US-03)]
                ├── 이름·비밀번호 변경
                └── 회원 탈퇴 (US-04): 확인 → 전체 데이터 삭제 → 로그인 화면
```

### 3-4. 할 일 상태 전이도

```
         등록
          │
          ▼
    [NOT_STARTED]  ◀──────────────────┐
          │  사용자 조작               │ 사용자 조작
          ▼                           │
    [IN_PROGRESS] ────────────────────┘
          │  사용자 조작
          ▼
       [DONE]

※ 날짜(startDate / dueDate) 변경은 저장 상태에 영향을 주지 않는다.
※ OVERDUE는 저장 상태가 아닌 조회 시 파생 상태:
   dueDate < 오늘 AND status ≠ DONE → 기한 초과 목록에 표시
```

## 4. 시나리오 상세

### US-01: 신규 가입 및 즉시 로그인

- 페르소나: P3 (신규 방문자)
- 연관 UC: UC-01
- 전제 조건: 사용자가 앱에 처음 접속한 미인증 상태
- 시나리오 흐름:
  1. 사용자가 회원가입 화면에서 이메일·비밀번호·이름을 입력한다
  2. 시스템이 이메일 형식 및 중복 여부, 비밀번호 규칙(8자 이상, 영문+숫자), 이름 길이(1~50자)를 검증한다
  3. 검증 통과 시 계정이 생성되고 '기본' 카테고리가 자동 생성된다
  4. 시스템이 인증 토큰을 발급하고 사용자를 즉시 로그인 상태로 전환한다
  5. themeMode가 LIGHT 기본값으로 적용된 메인 화면으로 이동한다
- 예외 흐름: 이메일 형식이 아닌 경우, 또는 비밀번호 규칙 미충족 시 해당 필드에 오류 메시지를 표시하고 가입을 중단한다 (US-18 참조)
- 완료 조건: 메인 화면에 로그인 상태로 진입하고 '기본' 카테고리가 존재한다

---

### US-02: 이메일·비밀번호로 로그인

- 페르소나: P1, P2
- 연관 UC: UC-02
- 전제 조건: 가입된 계정이 존재하며 로그아웃 상태
- 시나리오 흐름:
  1. 사용자가 로그인 화면에서 이메일과 비밀번호를 입력한다
  2. 시스템이 이메일·비밀번호 일치 여부를 확인한다
  3. 일치 시 인증 토큰을 발급한다
  4. 사용자의 저장된 themeMode(LIGHT 또는 DARK)가 즉시 적용된다
  5. 메인 화면으로 이동한다
- 예외 흐름: 이메일 또는 비밀번호가 일치하지 않으면 오류 메시지를 표시하고 로그인을 차단한다 (US-22 참조)
- 완료 조건: 메인 화면에 로그인 상태로 진입하고, 이전에 저장한 themeMode가 적용되어 있다

---

### US-03: 이름 및 비밀번호 수정

- 페르소나: P2
- 연관 UC: UC-03
- 전제 조건: 로그인 상태
- 시나리오 흐름:
  1. 사용자가 내 정보 수정 화면으로 이동한다
  2. 이름 변경 시: 새 이름(1~50자)을 입력하고 저장한다
  3. 비밀번호 변경 시: 현재 비밀번호를 먼저 입력하고, 새 비밀번호(8자 이상, 영문+숫자)를 입력 후 저장한다
  4. 시스템이 규칙을 검증하고 변경 사항을 저장한다
  5. 저장 성공 메시지를 표시한다
- 예외 흐름: 현재 비밀번호가 일치하지 않으면 오류 메시지를 표시하고 변경을 차단한다. 이름이 50자를 초과하거나 0자이면 오류를 표시한다
- 완료 조건: 변경된 이름 또는 비밀번호가 시스템에 반영된다

---

### US-04: 회원 탈퇴

- 페르소나: P1
- 연관 UC: UC-04
- 전제 조건: 로그인 상태, 등록된 할 일과 카테고리가 존재
- 시나리오 흐름:
  1. 사용자가 탈퇴 기능에 접근한다
  2. 시스템이 확인 절차(비밀번호 재입력 또는 확인 다이얼로그)를 제시한다
  3. 사용자가 확인을 완료한다
  4. 시스템이 해당 사용자의 모든 할 일, 카테고리('기본' 포함)를 삭제하고 계정을 제거한다
  5. 로그인 화면으로 이동한다
- 예외 흐름: 사용자가 확인 절차를 취소하면 탈퇴가 중단되고 현재 화면을 유지한다
- 완료 조건: 계정 및 모든 관련 데이터가 삭제되고 로그인 화면으로 이동한다

---

### US-05: 카테고리 생성

- 페르소나: P2
- 연관 UC: UC-05
- 전제 조건: 로그인 상태
- 시나리오 흐름:
  1. 사용자가 카테고리 생성 UI에 접근한다
  2. 카테고리 이름(1~30자)을 입력하고 생성 버튼을 클릭한다
  3. 시스템이 이름 길이를 검증하고 카테고리를 저장한다
  4. 생성된 카테고리가 본인의 카테고리 목록에 표시된다
- 예외 흐름: 이름이 0자이거나 30자를 초과하면 오류 메시지를 표시하고 생성을 차단한다
- 완료 조건: 새 카테고리가 본인 목록에만 표시된다

---

### US-06: 카테고리 삭제 및 할 일 이관

- 페르소나: P2
- 연관 UC: UC-06
- 전제 조건: 로그인 상태, 삭제 대상 사용자 정의 카테고리가 존재하며 해당 카테고리에 할 일이 포함되어 있음
- 시나리오 흐름:
  1. 사용자가 삭제할 카테고리를 선택한다
  2. 시스템이 확인 절차를 제시한다
  3. 사용자가 삭제를 확인한다
  4. 시스템이 해당 카테고리에 속한 할 일을 '기본' 카테고리로 자동 이관한다
  5. 카테고리가 삭제되고 목록에서 제거된다
- 예외 흐름: '기본' 카테고리(isDefault=true)에 대해 삭제를 시도하면 오류 메시지를 표시하고 삭제를 차단한다 (US-21 참조)
- 완료 조건: 카테고리가 삭제되고, 해당 카테고리의 할 일이 '기본' 카테고리로 이관되어 조회된다

---

### US-07: 할 일 등록

- 페르소나: P1
- 연관 UC: UC-07
- 전제 조건: 로그인 상태
- 시나리오 흐름:
  1. 사용자가 할 일 등록 화면으로 이동한다
  2. 제목(1~100자, 필수)을 입력한다
  3. 필요에 따라 설명(최대 1000자), 시작일, 종료일을 캘린더 UI로 선택한다
  4. 카테고리를 선택하거나 미지정 상태로 둔다
  5. 등록 버튼을 클릭한다
  6. 시스템이 입력값을 검증하고(제목 길이, 종료일>=시작일) 할 일을 저장한다
  7. 카테고리 미지정 시 '기본' 카테고리가 자동 적용된다
  8. 초기 상태 NOT_STARTED로 할 일이 목록에 나타난다
- 예외 흐름: 제목이 없거나 100자를 초과하면 오류를 표시한다. 종료일이 시작일보다 이전이면 오류를 표시한다 (US-19 참조)
- 완료 조건: 할 일이 NOT_STARTED 상태로 목록에 등록되고, 지정 카테고리(또는 '기본')에 분류된다

---

### US-08: 할 일 수정

- 페르소나: P2
- 연관 UC: UC-08
- 전제 조건: 로그인 상태, 본인이 등록한 할 일이 존재
- 시나리오 흐름:
  1. 사용자가 수정할 할 일을 선택한다
  2. 수정 화면에서 제목·설명·시작일·종료일·카테고리를 변경한다
  3. 저장 버튼을 클릭한다
  4. 시스템이 등록 규칙과 동일한 검증(제목 필수, 날짜 조건 등)을 수행하고 변경 사항을 저장한다
